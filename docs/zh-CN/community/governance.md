# 治理

本文档说明 Skill Wiki / Prime 项目的决策机制。模型设计上保持轻量：项目处于 pre-1.0 阶段，大多数决策可由具体工作的人快速拍板。下文的结构是在真正需要升级时的处理路径。

## v0.1.0 — 过渡期治理

**下文描述的结构是目标状态**，将在 v0.2.0 公开维护者征集后正式启动。v0.1.0 阶段：

- 项目只有一位作者，尚无技术委员会（TC）。
- 所有一级、二级、三级决策均由作者主导。
- RFC Issue（使用"Feature request"模板）会被阅读和考虑；最终决定由作者裁量。
- 三级决策的公开评审期从 v0.2.0 开始。

以下分级流程是项目演进为多维护者治理后的样貌，作为意图说明，而非 v0.1.0 日常运作的描述。

参见 [MAINTAINERS.zh-CN.md](./docs/zh-CN/community/maintainers.md) 了解 v0.1.0 的明确现状，以及如何在 v0.2.0 开放维护者时提名自己。

## 目标治理（v0.2.0 启动）

## 决策分级

### 一级——PR 内决策（任何有 PR 合并记录的人）

默认流程。若你的变更局限于一个包、有测试、不修改公开 API，并获得另一位贡献者的认可，直接合并即可，无需走正式流程。

示例：
- 不改变已文档化行为的 Bug 修复
- 新增测试
- 改进错误信息
- 在 `examples/` 语料库中添加新原子类型
- 文档改进
- Lint / 类型检查修复
- 无外部接口变更的内部重构

### 二级——触及 spec 的决策（技术委员会）

当变更涉及以下内容时：
- `.prime` DSL 语法
- 28 种声明的原子类型
- 14 种声明的边动词
- 3 种投影层级
- 5 层流水线
- `_index.xml` 或 `atom.yaml` 中的任意字段
- MCP `prime_query` 工具的 I/O 签名
- HTTP 注册中心的 REST 约定
- `domain.yaml` schema（参见 `spec/DOMAIN-EXTENSION-SPEC.md`）

……请先提一个 RFC Issue，使用"Feature request"模板并标注 **Scope: Spec change**。技术委员会（当前为 `MAINTAINERS.md` 中的维护者）进行评审；简单多数即可合并。默认响应时间：一周。

### 三级——修改章程的决策（公开共识）

保留用于：
- 修改项目使命声明
- 修改许可证（当前为 Apache-2.0）
- 项目重命名
- 在技术委员会中增减成员
- 采用行为准则

需经过 14 天公开评论期。决定需获得 > 50% 活跃维护者的明确同意，且近 6 个月内有 PR 合并记录的任何人不得有强硬反对。

## 角色

### 贡献者

至少有一个 PR 被合并的任何人。无需进一步承诺。

### 维护者

列于 `MAINTAINERS.md`。可以审查和合并 PR。需在约 7 天内响应提及自己的 Issue。

### 技术委员会（TC）

负责 spec 级别决策（二级）的维护者子集。TC 从创始维护者开始；候选人在成为维护者 ≥ 3 个月后，可由现有 TC 多数投票增设席位。

## 升级处理

如果你认为某个一级决策本应走二级流程：

1. 提一个标题为 `[escalate] <PR 编号或提交哈希>` 的 Issue
2. 说明你认为哪个 spec 不变量在未经 RFC 的情况下被修改
3. TC 有 7 天时间响应。沉默的默认结果是"该变更保留"。

## 投票

TC 投票（二级决策）在 Issue 讨论中公开进行，每位 TC 成员可投：
- `+1`（支持）
- `+0`（不反对）
- `-1`（反对，需附理由）

`-1` 阻止合并，直到提案人回应该理由，或 TC 以 2/3 多数投票推翻。

## 利益冲突

如果你对某个决策有利益关系（雇主产品受影响、个人有经济获益……），请在该 Issue 中回避投票并公开说明利益冲突。

## Spec 版本管理

协议 spec（`spec/PRIME-PROTOCOL-v1.md`）的版本独立于实现版本。实现可以是 `0.1.7`，而 spec 是 `1.0.0`。SemVer 规则：

- **Patch**：澄清说明、拼写修正，无行为变更
- **Minor**：向后兼容的添加（新原子类型、新边动词、新可选字段）。现有原子在新 spec 下仍可解析和编译。
- **Major**：破坏性变更（删除类型、重命名动词、修改必填字段）。需要迁移工具。

次要或主要级别的 spec 变更属于二级决策，需要 TC 明确的 `+1`。

## 修改本文档

本文档受三级规则约束——公开评论、14 天期限、> 50% 维护者同意。
