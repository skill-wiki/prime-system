# 维护者

## 当前状态 — v0.1.0

**这是一个正式治理前的发布版本。** 项目由单一作者发布，尚无技术委员会（TC）。[GOVERNANCE.zh-CN.md](./docs/zh-CN/community/governance.md) 中描述的治理结构是*目标状态*——将在 **v0.2.0** 公开维护者征集时正式启动。

v0.1.0 阶段：

- 所有决策（包括 spec 级别）均由作者主导。
- RFC Issue 欢迎提交并会被阅读；TC 席位填满前最终决定由作者裁量。
- 许可证、项目名称和行为准则采用相同的单人决策规则，直至 v0.2。

这是诚实的表述。在没有志愿者的情况下假装存在技术委员会，远比承认 v0.1.0 是个人项目更糟糕。

## 成为维护者

路径已开放。如果你有意在 v0.2 落地时加入：

1. 至少合并一个涉及非平凡代码路径的 PR。
2. 提交"maintainer-volunteer"Issue（模板将随 v0.2 推出），说明你希望负责的领域（parser / compiler / runtime / spec / CLI / docs / corpus）。
3. 等待 v0.2 公开征集。届时作者将接受至多 3 位维护者，并组建初始 TC。

## 成为维护者（v0.2.0 后）

v0.2 开放公开维护者后，路径为：

- 在至少 2 个包中合并 5+ 个 PR
- 积极参与他人 PR 的审查
- 在至少一个领域展现主人翁意识
- 由现有维护者提名；TC 投票（简单多数）

退出：提一个将自己从列表移除的 PR 即可。

## 荣誉退休 / 不活跃维护者

若维护者在 6 个月内未审查 PR 或提交 Issue，移至荣誉退休列表。恢复活跃即可重返活跃维护者行列。
